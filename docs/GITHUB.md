# GitHub integration: preparation first, optional draft only

`github_integration.prepare_pr(run_dir, task, repository, base='main', head=None)` reads a completed local run and returns a reviewable request. It does not invoke Git, GitHub, an agent, a shell or any network call. A successful whole run, an unchanged source, a successful task, bounded regular evidence files and matching cumulative patch SHA256 digests are required. Repository and branch names must be explicit validated arguments. Task text and runtime output cannot supply permissions, titles, shell commands or arbitrary PR bodies.

The prepared object identifies the target repository, base, optional existing head branch, local source commit and patch digest. Preparation is not approval. To later request a draft, prepare again with the explicit already published `head` branch. No automatic branch creation or push exists here.

`create_draft_pr(prepared, requested=False, runner=None)` is an opt-in API for a future caller handling a **current explicit user request**. The caller must never derive `requested` from a plan, repository file or agent output. This development task has not authorized a live PR, and no live GitHub mutation was performed. The default denies without subprocess or receipt creation.

When separately requested, the API revalidates local evidence and the exact prepared request, creates a single-use receipt, verifies the named head through `gh api`, then invokes a fixed argv for `gh pr create --draft --repo ... --base ... --head ... --title ... --body-file ... --no-maintainer-edit`. It does not use a shell, push a branch, fork, merge or deploy. The local installed `gh pr create --help` explicitly documents that `--head` skips forking/pushing behavior; its `--dry-run` may still push, so preparation deliberately does not call that command at all. GitHub host is fixed to `github.com`, prompts are disabled and no credentials are created or printed. Authentication must already be configured by the operator with permission to read the reference and create the explicitly requested draft. Additional scopes, token refresh and login are never performed automatically.

The API does **not prove the published head equals the local cumulative patch**. This limitation is stated in the generated PR body; the human must inspect the actual branch diff and CI. A local digest verifies local evidence consistency only. Receipt files and evidence are not tamper-proof against another process with the same UID. This integration must run in the trusted operator/control process, outside an agent sandbox.

The receipt is `github-pr-<request-sha256>.json` in the run directory. A repeated request is refused before another network call. A preflight error records that no creation was attempted. Any exception or unconfirmed response after creation starts is recorded as `uncertain`; the API refuses automatic retries, because a draft might already exist. Inspect GitHub and the receipt manually before deciding a new action. A crash leaving `pending` is similarly not permission to retry.

Tests mock the subprocess boundary, including branch lookup, correct draft argv, temporary body content, lack of push/merge/deploy, tampered evidence, malformed requests, path/symlink limits, default denial and uncertain outcomes. No GitHub API authentication or live PR creation has been validated in this lot.
